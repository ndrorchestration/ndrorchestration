### AI Systems Design · Agentic Orchestration · Evaluation & Governance

I design and test AI systems around three questions:

**What can the system do? What does the evidence support? What is it authorized to do next?**

My work brings prompt engineering, agentic orchestration, evaluation methodology and software reliability together. I am interested in making AI systems more inspectable, accountable and useful — without mistaking complexity for intelligence or confidence for evidence.

## Five flagship projects

### 01 — [Agentic Governance Orchestrator](https://github.com/ndrorchestration/DGAF-Framework)

**Evidence-bound agentic governance and assurance | Experimental research system**

Agentic Governance Orchestrator is the proposed successor name for **Dynamic Governance Agentic Formation (DGAF)**. It explores a control-plane architecture in which evidence, verification, capability, authority and permission to act are distinct machine-relevant states.

- **Engineering:** fail-closed authorization, deterministic validators, provenance binding, governed state transitions, content-addressed evidence receipts and research custody.
- **Orchestration research:** governed agent formations, role-scoped capabilities and explicit control boundaries. Broader durable, interoperable and adaptive orchestration is a development direction, not a completed capability claim.
- **Comparative evidence:** a conventional policy-as-code comparator matched 13/13 fixed fixtures and all 112,200 bounded synthetic states, with zero allow/deny differences. Unique decision-policy superiority was not demonstrated. The additional value of the assurance lifecycle remains under evaluation.
- **Research discipline:** Track A Epoch 002 closed at its exact preregistered scope; its 50 paired seed units and 2,250 observations do not establish canonical efficacy or independent validation.

**Explore:** [Bounded public demo](https://project-7ybao.vercel.app/demo) · [Technical orientation](https://github.com/ndrorchestration/DGAF-Framework/blob/main/README.technical.md) · [Current evidence state](https://github.com/ndrorchestration/DGAF-Framework/blob/main/docs/CURRENT_STATE.md)

**Boundary:** PRE-FREEZE / FAIL-CLOSED / NOT AUTHORIZED. Scientific N increment = 0; canonical efficacy and independent validation NOT ESTABLISHED; High-Assurance NOT AUTHORIZED.

### 02 — [Agent Control Plane (ACP)](https://github.com/ndrorchestration/agent-control-plane)

**Deterministic execution control | Experimental Python kernel**

ACP explores the machinery around agent execution: task identity, capability dispatch, policy decisions, budgets, cancellation and run-scoped provenance.

- **Engineering:** typed execution contracts, fail-closed capability checks, bounded supervisor candidates and disposable-repository execution controls.
- **Efficiency research:** the Context Efficiency Plane reduced exposed capability descriptors from 89 to 1 on a frozen connector-metadata snapshot, preserving the required descriptor. This characterizes catalog exposure, not live-model efficiency.

**Explore:** [Implementation inventory](https://github.com/ndrorchestration/agent-control-plane/blob/main/docs/CURRENT_IMPLEMENTATION_INVENTORY.md) · [Bounded executor PR #156](https://github.com/ndrorchestration/agent-control-plane/pull/156)

**Boundary:** BOUNDED_LOCAL_TEST. Production execution, real-project mutation authority and independent validation are not established.

### 03 — [Orbit-Driftwatch](https://github.com/ndrorchestration/Orbit-Driftwatch)

**Observable multi-agent reasoning | Evaluation and observability**

Instead of presenting only a final answer, Orbit-Driftwatch exposes how a workflow reaches it: role observations, source bindings, disagreement, evidence coverage and unsupported claims.

- **Engineering:** Planner / Researcher / Skeptic / Verifier roles, deterministic control, provider abstraction, retrieval architecture and claim-readiness auditing.
- **Review:** run the reproducible default without model credentials; inspect the fail-closed claim audit and frozen run artifacts.

**Explore:** [Five-minute evaluator path](https://github.com/ndrorchestration/Orbit-Driftwatch#five-minute-evaluation-path)

**Boundary:** deterministic controls are verified; live hosted provider execution and factual correctness are separate claims.

### 04 — [ResumeApex Eval Suite](https://github.com/ndrorchestration/resumeapex-eval)

**Reproducible AI evaluation | Python evaluation harness**

A practical evaluation system for resume and career-assistance tasks, using the repository-defined Goldcanstaytoday protocol.

- **Engineering:** known-answer fixtures, deterministic repeatability, metric computation, bootstrap analysis and structured reporting.
- **Methodology:** distinguishes a defined rubric, implemented evaluator, verified fixture behavior and empirically executed model/corpus evaluation.

**Explore:** [Protocol specification](https://github.com/ndrorchestration/resumeapex-eval/blob/main/docs/specs/goldcanstaytoday_spec_v1.md) · [Quick start](https://github.com/ndrorchestration/resumeapex-eval#quick-start)

**Boundary:** known-answer fixture verification does not establish real-model benchmark performance.

### 05 — [Collabration](https://github.com/ndrorchestration/Collabration)

**Accountable human–AI collaboration | Alpha-stage product engineering**

A social application exploring a familiar human experience supported by governed AI capabilities. **Metacollaborate. Metacalibrate. Metacelebrate.**

- **Engineering:** explicit capability policy, human approvals, provenance and revision-aware Content Passports, correction and appeal, authenticated flows and row-level security.
- **Product design:** users should be able to understand what AI contributed, who authorized an action and how a result can be challenged.

**Explore:** [Five-minute evaluator path](https://github.com/ndrorchestration/Collabration#five-minute-evaluator-path)

**Boundary:** alpha application; production persistence, security and release readiness require separate verification.

## My approach

Defined, implemented, tested, verified, independently verified, authorized and empirically supported are different states.

A passing test does not prove efficacy. Provenance establishes origin, not truth. An agent's capability is not permission. A useful system must make its limits as inspectable as its successes.

I welcome independent scrutiny, reproducible findings and negative results. For the flagship research, see the [independent reproduction gate](https://github.com/ndrorchestration/DGAF-Framework/issues/1067) and [outside-operator trial](https://github.com/ndrorchestration/DGAF-Framework/issues/1210). Neither is an achieved independent-validation claim.
